# قائمة القبول والاختبار — تحديث المحاكمة القادم

## 1. البناء

- [ ] `testDebugUnitTest` ينجح.
- [ ] `assembleDebug` ينجح.
- [ ] `connectedDebugAndroidTest` ينجح.
- [ ] لا توجد أخطاء lint حرجة أو تحذيرات Kotlin جديدة غير مفسرة.
- [ ] لم تتغير package name أو applicationId أو مفاتيح DataStore القديمة.

## 2. سلامة بنك الأسئلة والمسارات

- [ ] `QuestionBankAudit.inspect()` يرى 1000 سؤالًا و1000 معرف فريد.
- [ ] جميع الأسئلة قابلة للوصول من `q01`.
- [ ] لا توجد روابط `nextQuestionId` مفقودة أو عائدة إلى عقدة سابقة.
- [ ] لكل سؤال ثلاثة خيارات بمعرفات مستقلة ونصوص ووسوم مناسبة.
- [ ] تراجع التحذيرات المحتملة للصياغات المتكررة يدويًا؛ التحذير لا يعني تلقائيًا وجود خطأ.

- [ ] بدء المحاكمة من q01 يصل إلى سؤال صحيح.
- [ ] تغيير إجابة مبكرة يحذف إجابات الفرع القديم من `UserState.answers` كما يفعل المستودع حاليًا.
- [ ] التحليل الجديد لا يرى إلا `QuestionnaireEngine.activePath`.
- [ ] سجل التاريخ يحتفظ بإجابة الفرع القديم لكنه يضعها في حالة «من مسار سابق».
- [ ] لا يحدث تكرار في احتساب الإجابة نفسها عند إعادة فتح شاشة.

## 3. شجرة الوجوه

- [ ] تظهر الوجوه السبعة كلها.
- [ ] كل edge يشير إلى وجه موجود.
- [ ] الضغط على وجه يعرض تفاصيله.
- [ ] الأدلة المؤيدة تعود إلى أسئلة فعلية.
- [ ] الأدلة المضادة لا تتضمن إجابة من فرع غير نشط عند عرض الملف الحالي.
- [ ] التنقل إلى وجه مرتبط يعمل.
- [ ] الوجوه ذات score صفر لا توصف بأنها «موجودة» أو «مؤكدة».
- [ ] النص يوضح أن الدرجات ليست احتمالًا أو تشخيصًا.

## 4. طيف الروح والذاكرة

- [ ] يحافظ `activeBranchMemory` على السجل الأصلي ولا يستبدله.
- [ ] الإجابات القديمة المتعارضة لا تدخل في `createInsight` الحالي.
- [ ] أحداث feedback تبقى محفوظة.
- [ ] يظهر للمستخدم دليل الملاحظة وحدودها.
- [ ] اعتراض المستخدم يبقى محفوظًا.
- [ ] ظهور الطيف لا يغيّر صوت الأوركسترا أو توقيته أو سلوكه دون موافقة.

## 5. سجل التطور

- [ ] أول snapshot لا يُحفظ مع صفر إجابات.
- [ ] snapshots تُحفظ على milestones المحددة فقط.
- [ ] compare يحدد الوجوه الجديدة والمتراجعة والتوترات الجديدة والمحسومة.
- [ ] timeline يعرض الأحدث أولًا.
- [ ] الإجابات الحالية مميزة عن الإجابات القديمة.
- [ ] وقت الحدث المعروض يعتمد على timestamp الأصلي.
- [ ] السجل يتحمل الأحداث غير المعروفة دون انهيار.

## 6. المحكمة الداخلية

- [ ] تتولد قضية من أقوى توتر إذا توفرت أدلة.
- [ ] عند نقص الأدلة تظهر قضية مفتوحة بدل اختلاق نمط.
- [ ] لا يسمح بحفظ محضر دون موقف ودليل.
- [ ] confidence محصورة بين 0 و100.
- [ ] المحضر يتضمن سؤالًا يمكن أن يغير الموقف.
- [ ] المحضر يظهر في سجل التطور بعد إعادة تشغيل التطبيق.

## 7. التوافق مع التطبيق الحالي

- [ ] إدخال الاسم أول تشغيل كما كان.
- [ ] بقاء الإعدادات الصوتية وقيم الكتم والمسار المختار.
- [ ] بقاء ساعة المحاكمة التراكمية.
- [ ] استمرار عمل الأسئلة الحالية ومساراتها.
- [ ] بقاء شاشة «صدى الماضي» والغرفة الصامتة وبقية الأقسام.
- [ ] بقاء فيديو `spirit_specter.mp4` والموارد الصوتية والمرئية.
- [ ] عدم تغير تسلسل مقاطع الأوركسترا الثمانية.
- [ ] لا صوت أو فيديو غير مقصود عند الانتقال للخلفية.

## 8. اختبار هاتف حقيقي

- [ ] تثبيت APK على جهاز أندرويد حقيقي.
- [ ] فتح الشجرة والتفاعل معها بيد واحدة وعلى شاشة صغيرة.
- [ ] التأكد من أن النصوص لا تتجاوز حدود الشاشة.
- [ ] اختبار الرجوع والتنقل المتكرر.
- [ ] إغلاق التطبيق قسريًا وإعادة فتحه والتحقق من الاستعادة.
- [ ] تجربة تشغيل الفيديو والصوت ومراقبة الذاكرة والحرارة.
- [ ] التأكد من أن التطبيق لا يتوقف عند انتهاء مقطع أو عند عودة المستخدم من الخلفية.

## 9. قرار الإصدار

لا تُرفع نسخة للمستخدم النهائي إلا إذا نجحت اختبارات البناء والوحدات والمحاكي، ثم نجحت قائمة الهاتف الحقيقي الأساسية. نجاح `assembleDebug` وحده لا يعني أن التحديث جاهز للنشر. لا تدمج إلى `main` قبل مراجعة commit والفروقات والموافقة الصريحة.
